The subject remains Flux kustomize-controller v1.10.1, commit
`746d9d2d360bbc7a5ee75ab79dadcf05e48ab927`, using native `--concurrent=10`.
Both deployment snapshots and native startup logs confirm ten reconciliation

It does not run source-controller or any other Flux operator.

The source-informed hypothesis was that inventory and pruning recover when the
controller is restarted after a rejected prune attempt returns, before its caller
can merge survivors into status inventory. The source already contains
[failed-prune retention from upstream #1665](https://github.com/fluxcd/kustomize-controller/pull/1665).
The pinned [SSA delete implementation](https://github.com/fluxcd/pkg/blob/ssa/v0.83.0/ssa/manager_delete.go)
checks owner labels and prune exclusions. Recovery here validates those existing
behaviors across the selected interruption; it is not a rediscovery claim.
