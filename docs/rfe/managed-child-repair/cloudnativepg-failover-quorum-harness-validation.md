# CloudNativePG FailoverQuorum harness repair and bounded rerun

**The repaired harness exposed and confirmed an operator safety failure in both matched fault attempts.** Delayed FailoverQuorum reset/update delivery left the operator using stale W2 metadata after required synchronous replication changed from ANY 2 to ANY 1. With only replica A available, it accepted R1/W2/N2, acquired A's primary lease and promoted A while A lacked an acknowledged remote_apply witness. Successful client reads regressed below acknowledged-write bounds. All four no-fault workloads passed independent physical and client checks.

Harness repair commit `20a1fed1106394b367d29c8568c36a2925a1561b` routes API callbacks for scoped/all delivery pauses even when triggers observe another resource, releases every waiter by closing the pause channel, handles resume without a waiter, creates fresh later pause channels, returns cancellation errors, and locks shared pause maps. Concurrent public RPC tests also exposed a mask-cache lookup race; its existing mutex now covers the lookup, with mask contents unchanged. Five RED/GREEN slices used the user-approved public client/coordinator RPC seam. All three Go modules passed race tests and vet. All 413 allowed Python tests, lint/format, strict type checks for 38 configured sources and the wheel build passed. The protected test was excluded and unchanged. Failed intermediate tests/reviewer drafts are retained with correction notes.

Native CloudNativePG remained pinned to `96cb6b05aea5f76ddac43d21e0f178e0a8b1b331`. Fresh learn/test controller and API images contain the repaired shared client. Independent build review checked 964 original native Go files, the exact existing learning observation patch, unchanged test-mode native source before instrumentation and 115 declared dependency versions. Native Go 1.26.4/client-go 0.36.2/controller-runtime 0.24.1, API Go 1.26.10/Kubernetes v1.36.4, actual API binaries, OCI index/manifest/layer provenance and Kind input archives were verified. The vanilla instance-manager identity remained fixed. These are recorded per-instance final losses and client-visible acknowledgement regressions. An old branch can retain earlier rows while lacking later acknowledgements; global or irrecoverable erasure is not established. The native source resets quorum status before reloading PostgreSQL and republishes afterward, while the operator's cached Get evaluates R+W>N using the returned object without establishing freshness across that effective configuration change. The actual cache Get and native acceptance support this causal explanation; no fabricated metadata, forced promotion or manual quorum-status update was used.
